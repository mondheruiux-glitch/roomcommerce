Product Overview & Problem Statement1.1 Executive OverviewProject RoomCommerce is an AI-powered spatial redesign and multi-retailer commerce engine. It enables users to photograph any domestic interior space and receive a photorealistic, physically plausible redesign populated entirely with verified, in-stock, purchasable furniture and decor from major retail catalogs (e.g., IKEA, Target, Wayfair, Amazon, West Elm). Every newly rendered object functions as an interactive hotspot providing real-time pricing, spatial dimensions, and localized direct-checkout affiliate links.1.2 Problem StatementConsumers redecorating or moving into a living space experience severe friction between spatial discovery and commercial procurement:The Inspiration Dead-End: Generative design tools (e.g., Midjourney, RoomsGPT) synthesize fictional furniture that cannot be purchased, creating unmet consumer expectations.The Walled-Garden Constraint: Retailer-specific visualizers (e.g., IKEA Kreativ, Wayfair Decorify) restrict recommendations to a single brand catalog, failing the real-world consumer behavior of mixing and matching items across price points and vendors.The Spatial Fit Failure: E-commerce furniture returns average 15% to 25%, with the leading driver being dimensional and aesthetic mismatch ("it looked smaller online" or "it clashed with the existing room").The Curation Labor Tax: Manually cross-referencing floor measurements, matching color swatches, hunting for visually similar in-stock SKUs, and tracking a holistic budget across multiple tabs creates cognitive fatigue and high cart abandonment.2. 5. Functional Requirements (FR)Status Taxonomy: [Approved] = Formally accepted; [Proposed] = Under PM review; [Unresolved] = Pending business/technical rule definition.5.1 Image Capture, Spatial Pre-Processing & AnchoringFR-101 [Approved] Image Upload & Validation: The system must accept JPG, PNG, and HEIC room photos up to 20MB via direct upload or mobile camera capture.FR-102 [Approved] Automated EXIF & Metadata Scrubbing: All client-side metadata, device telemetry, and geolocation GPS tags must be stripped before image transmission to cloud object storage.FR-103 [Approved] Monocular Depth & Room Geometry Estimation: The backend must compute a relative depth map and semantic wall/floor segmentation mask from a single 2D input image to enforce boundary surfaces.FR-104 [Proposed] Object Detection & Anchor Locking (Keep Existing Items): The UI must allow users to tap detected bounding boxes (e.g., current sofa, existing hardwood floor) to "lock" them, preventing the inpainting model from altering those designated regions.FR-105 [Proposed] Quality Gate Validation: The system must detect and reject photos that lack recognizable room surfaces, are excessively blurry, or are under-illuminated, returning actionable remediation guidance.5.2 Style, Budget & Constraint ConfigurationFR-201 [Approved] Aesthetic Style Selector: Users must select from a fixed taxonomy of at least 8 curated style presets: Mid-Century Modern, Japandi, Scandinavian, Industrial, Minimalist, Contemporary, Bohemian, and Modern Farmhouse.FR-202 [Approved] Total Room Budget Guardrail: Users must be able to specify a total room expenditure ceiling (range: $300 to $10,000 in local currency).FR-203 [Proposed] Room Function Selection: Users must select the target functional room type: Living Room, Bedroom, Home Office, Dining Room, or Patio/Balcony.FR-204 [Unresolved] Retailer Filter Exclusion: Ability for users to toggle specific retailers on or off (e.g., "Exclude Amazon" or "IKEA Only"). (Unresolved: Evaluating whether retailer exclusion degrades vector match density in small budgets).5.3 Inpainting, Rendering & Visual-to-SKU MatchingFR-301 [Approved] Depth-Guided Spatial Inpainting: The generative pipeline must synthesize a restyled interior maintaining wall boundaries, window locations, lighting direction, and floor plane perspective.FR-302 [Approved] Multi-Object Instance Segmentation: The system must segment all newly placed furniture and decor assets into discrete item bounding masks.FR-303 [Approved] Multimodal Vector Similarity Search: Each segmented item crop must query a pre-indexed vector catalog (using SigLIP/CLIP embeddings) to retrieve the top 3 highest-similarity real-world SKUs.FR-304 [Approved] Dimension & Budget Post-Filtering: The search retrieval engine must filter candidate SKUs against estimated bounding dimensions and verify that individual item prices do not breach the cumulative room budget ceiling.FR-305 [Proposed] Alternative Match Carousel: Tapping a product hotspot must display the primary match and allow the user to swipe through at least two viable alternative SKUs (e.g., "Budget Alternative" and "Premium Alternative").5.4 Shoppable Canvas & Outbound CommerceFR-401 [Approved] Interactive Hotspot Canvas: The rendered output must display interactive, pulsing pin markers over each newly generated piece of furniture.FR-402 [Approved] Product Detail Modal: Tapping an interactive pin must present:Product Title and Brand/Retailer Logo.Live Retail Price and Currency Symbol.Physical Dimensions (Height, Width, Depth).Perceived Similarity Confidence Score (e.g., "Exact SKU" vs. "92% Visual Match").Primary CTA: "View at [Retailer Name]".FR-403 [Approved] Programmatic Affiliate Deep-Linking: Tapping the outbound CTA must route the user through the appropriate affiliate tracker (e.g., Impact, CJ, Amazon Associates) with active click IDs and redirect to the canonical product listing page in a new browser tab.FR-404 [Proposed] Universal Room Basket View: The system must provide a slide-up summary sheet displaying the itemized total cost of all rendered items relative to the user's budget ceiling, with a "Copy All Links" action.5.5 Monetization & Entitlements EngineFR-501 [Approved] "Move-In Project Pass" Purchase Flow: Integration with Stripe (Web) and In-App Purchases (iOS StoreKit 2) to purchase a $14.99 30-day episodic pass.FR-502 [Approved] Pay-as-You-Go Credit Packs: Integration allowing users to purchase a 5-render credit pack for $4.99.FR-503 [Approved] Watermark Enforcement: Non-paying users (Free Tier) receive rendered images with a semi-transparent diagonal Project RoomCommerce watermark and standard definition resolution (1080p maximum).FR-504 [Approved] Paid Entitlement Unlocks: Active Pass holders receive watermark-free 4K downloads, anchor locking capabilities, and unlimited generations (governed by fair-use throttling).6. Non-Functional Requirements (NFR)6.1 Performance & LatencyNFR-01 [Approved] Generation Turnaround Time: End-to-end pipeline latency (photo upload $\rightarrow$ depth pass $\rightarrow$ inpainting $\rightarrow$ segmentation $\rightarrow$ vector query $\rightarrow$ hotspot render) must complete in $\le 15.0\text{ seconds}$ for the 90th percentile under normal network conditions.NFR-02 [Approved] Hotspot Interaction Latency: Tapping a product pin must render the product detail sheet in $\le 150\text{ milliseconds}$.NFR-03 [Approved] Vector Database Query Latency: Candidate SKU embedding search across $\ge 250,000$ catalog items must execute in $\le 80\text{ milliseconds}$ per object.6.2 Availability, Scalability & ReliabilityNFR-04 [Approved] Service Uptime: Core web application and API endpoints must maintain $99.9\%$ monthly availability (excluding scheduled maintenance windows).NFR-05 [Approved] Auto-Scaling Inference Workers: GPU inference worker pools must auto-scale horizontally to support a burst load of at least 50 concurrent room generation requests without queue timeouts.NFR-06 [Proposed] Graceful Degradation Under Load: If GPU inference queue wait time exceeds 25 seconds, the system must display an asynchronous polling notification: "High rendering demand; your room is being processed. We will notify you when ready."6.3 Data Freshness & Catalog AccuracyNFR-07 [Approved] Catalog Price & Stock Synchronicity: Retailer SKU pricing and in-stock flags must be refreshed via automated feed crawlers at least once every 24 hours.NFR-08 [Approved] Broken Link Prevention: Outbound affiliate redirect endpoints must validate target URL HTTP response codes daily; dead URLs (404/410) must be automatically suppressed from the vector retrieval pool.7. Business Rules & Workflows7.1 Business Rules (BR)BR-01 [Approved] Fair Use Cap on 30-Day Passes: To protect against commercial scraping or abuse, a $14.99 Move-In Pass is limited to a fair-use ceiling of 60 high-resolution generations per 30-day period. Generations beyond 60 require an additional credit pack.BR-02 [Approved] In-Stock Guarantee Threshold: The system must never assign a product pin to a SKU marked as "Out of Stock" or "Discontinued" in the catalog database at the time of query execution.BR-03 [Approved] Mandatory FTC Affiliate Disclosure: Every screen presenting shoppable links must display prominent legal disclosure text: "We may earn an affiliate commission from qualifying purchases made via links on this page."BR-04 [Unresolved] Return Policy on Digital Passes: If a user purchases a Move-In Pass but the AI fails to generate acceptable rooms due to repeated edge-case photo errors, what is the automated refund policy window (e.g., 7 days if fewer than 3 renders executed)?7.2 Core End-to-End User Generation Workflow[User Uploads Room Photo]

10. Security, Privacy & Accessibility10.1 Security RequirementsSEC-01 [Approved] Ephemeral Raw Photo Storage: Original raw interior photographs uploaded by users must be permanently purged from cloud storage after 7 days, retaining only the processed spatial feature vectors and final generated renders.SEC-02 [Approved] Automated Facial & PII Obfuscation: The server-side intake pipeline must automatically apply a Gaussian blur to any detected human faces, family portraits, or text-heavy documents captured in room photos prior to running inpainting.SEC-03 [Approved] End-to-End Encryption: All spatial imagery and API payload transmissions must be encrypted in transit via TLS 1.3 and at rest via AES-256 encryption.10.2 Privacy & Regulatory CompliancePRV-01 [Approved] GDPR / CCPA Zero-Model-Training Guarantee: User-submitted domestic interior imagery must be explicitly quarantined and excluded from training public foundation models without affirmative opt-in consent.PRV-02 [Approved] Right to Full Erasure: The user profile settings must provide a one-click "Delete All Project Data & Room Photos" action that executes hard deletion across databases, S3 buckets, and vector indices within 24 hours.10.3 Accessibility RequirementsACC-01 [Approved] WCAG 2.1 Level AA Compliance: The web and mobile interfaces must conform to WCAG 2.1 AA standards, including color contrast ratios of at least 4.5:1 for all text elements.ACC-02 [Approved] Screen-Reader Compatible Shoppable List: Because spatial image pins are purely visual, the system must provide an accessible, structured DOM table/list alternative presenting each item's name, brand, price, and affiliate URL labeled with clear aria attributes.11. User Stories & Testable Acceptance CriteriaUS-01: First-Time Room Transformation & Hotspot GenerationAs a transitional mover furnishing an apartment,I want to take a photo of my empty living room and pick a design style and budget,So that I get an inspirational redesign filled with real products I can actually buy.Scenario 1: Successful end-to-end generationGiven a user has uploaded a clear photo of an indoor living room,When they select the "Japandi" style and set a budget of "$1,500",Then the system returns a redesigned render in less than 15 seconds,And displays between 3 and 7 interactive product pins,And the sum of all primary matched items does not exceed $1,500.Scenario 2: Low-quality or non-room photo rejectedGiven a user uploads an image of an outdoor highway or a heavily blurred photo,When the validation gate analyzes the image,Then the image is rejected before invoking the GPU inpainting model,And an error message is displayed explaining how to frame a valid room photo.US-02: Outbound Product Procurement via Pin InteractionAs a prospective buyer,I want to tap a coffee table in the redesigned room image,So that I can view its price, brand, and dimensions, and click through to purchase it on the retailer's store.Scenario 1: Tapping an in-stock product pinGiven a generated room render with visible pins,When the user taps the pin located on the coffee table,Then a product card slides up in under 150ms showing the product title, retailer name, price, dimensions, and similarity rating,When the user clicks "View at Retailer",Then a new browser tab opens navigating to the retailer's canonical page with the affiliate tracking parameters appended.Scenario 2: Viewing alternative optionsGiven the product card is open for an item,When the user swipes left on the card,Then the card displays an alternative SKU that matches the same category and style within the budget.US-03: Anchor Item Locking (Preserving Existing Furniture)As an incremental room refresher,I want to lock my existing leather sofa in place,So that the AI designs around it rather than replacing it with a new sofa.Scenario 1: Masking an anchor itemGiven a user with an active Move-In Pass has uploaded a room containing a sofa,When the user taps the detected bounding box of the sofa and toggles "Keep This Item",Then the sofa region is masked from the diffusion inpainting prompt,And the resulting render retains the original sofa with updated surrounding rugs, tables, lighting, and decor.14.
