# 3. Security Architecture & Technical Controls

### 3.1 Authentication, Sessions & Access Control
* **Passwordless Magic Links:** 
  * Tokens generated via `crypto.randomBytes(32).toString('hex')`.
  * Hashed using SHA-256 before storage in Redis with a 15-minute TTL.
  * Consuming a token immediately deletes it from Redis (`GETDEL`), preventing replay attacks.
* **Session Cookies:**
  * Transported exclusively via `HttpOnly`, `Secure`, `SameSite=Lax` cookies.
  * Signed using a rotating HMAC secret.
  * Absolute session lifetime: 14 days; idle session timeout: 72 hours.
* **Role-Based Entitlement Enforcement (RBAC):**
  * `EntitlementGuard` inspects the user's active pass state directly against Aurora PostgreSQL before dispatching any render job or 4K asset retrieval.
  * BOLA/IDOR Defense: Every request querying `/api/v1/projects/:id` strictly asserts `WHERE id = :id AND (user_id = :current_user_id OR guest_session_id = :current_guest_id)`.

### 3.2 File Upload & Processing Security
Direct-to-storage uploads through presigned URLs prevent malicious payloads from exhausting web server resources, but require strict perimeter verification:


```

[Client Request: POST /api/v1/projects]
│
▼
[API Gateway / NestJS Intake Verification]
├── Rate Limit: Max 5 upload requests per minute per IP.
├── Validate requested Content-Type: `image/jpeg`, `image/png`, `image/heic` (Strict Whitelist).
├── Generate random asset key: `raw-uploads/{uuidv4}.{ext}` (No client-controlled filenames).
└── Issue Presigned PUT URL: Restricted to exact `Content-Length` (<= 20,971,520 bytes), TTL = 300s.
│
▼
[Client Executes Direct PUT to Cloudflare R2]
│
▼
[Trigger Worker Validation on Ingestion]
├── Step 1: Magic Byte / File Signature Inspection (Verify real JPEG/PNG/HEIC headers).
├── Step 2: Decompression Bomb Guard: Reject if dimensions > 4096 x 4096 or uncompressed > 100MB.
├── Step 3: Strip remaining EXIF metadata using PyExifTool / Pillow.
└── Step 4: Re-encode image into sanitized canonical RGB array before feeding to ML models.

```

### 3.3 Payment Integrity & Webhook Security (Stripe)
* **PCI DSS Compliance Scope:** Minimized to **SAQ-A**. No payment credentials (credit card numbers, CVVs) ever touch the application's servers. Payments are handled via Stripe Elements and Checkout sessions.
* **Webhook Hardening:**
  * Raw body parsing enabled exclusively for `/api/v1/billing/webhook` to preserve raw payload bytes for HMAC verification.
  * Verification uses `stripe.webhooks.constructEvent(rawBody, signature, endpointSecret)`.
  * Replay Protection: Timestamp tolerance enforced ($\le 300\text{ seconds}$).
  * Webhook idempotency enforced via PostgreSQL unique constraint on `stripe_session_id`. Duplicate webhook deliveries yield an immediate HTTP 200 without re-processing.
* **Zero Client Price Trust:** Price amounts ($14.99) and currency (USD) are hardcoded on the server. The client never passes financial amounts to the API.

# 5. Data Privacy, Minimization & Regulatory Assessment

### 5.1 Ephemeral Storage & The 7-Day Purge Architecture
To comply with GDPR Article 5(1)(e) (Storage Limitation), the application enforces automated, multi-tier data destruction:


```

[Day 0: User Uploads Room & Renders Design]
│ • Image stored in Cloudflare R2: `raw-uploads/{uuid}.jpg` and `renders/{uuid}.webp`
│ • PostgreSQL `projects` record set with `purge_scheduled_at = NOW() + INTERVAL '7 days'`
│
[Day 7: Automated Dual Purge Execution]
├── TIER 1: Cloudflare R2 Bucket Lifecycle Policy
│   └── Automatically hard-deletes any object matching `raw-uploads/*` or `renders/*`
│       with age > 7 days (Zero reliance on application code for deletion).
│
└── TIER 2: Backend Cleanup Daemon (Cron at 03:00 UTC Daily)
└── Executes: `DELETE FROM projects WHERE purge_scheduled_at <= NOW()`
Cascading foreign keys delete associated hotspots and vector cache pointers.

```

### 5.2 Right to Erasure: 1-Click Hard Purge Implementation
Users can execute an immediate purge via `/account` (`PRV-02`):
1. **Endpoint:** `DELETE /api/v1/account/data` (Requires passwordless re-authentication or active session confirmation).
2. **Execution:**
   * Deletes all user objects in Cloudflare R2 via batch DeleteObjects API.
   * Hard-deletes all database rows in `users`, `move_passes`, `projects`, and `canvas_hotspots`.
   * Invalidates Redis cache sessions and telemetry associations.
   * Returns confirmation within 60 seconds.

# 6. Supply-Chain & Dependency Hardening

Modern Node.js and Python ML stacks carry severe supply-chain vulnerability risks (e.g., malicious PyPI packages, compromised npm sub-dependencies):

1. **Model Weight Provenance:**
   * All ML model weights (`Depth-Anything-V2-Base`, `controlnet-depth-sdxl-1.0`, `siglip-so400m-patch14-384`) are downloaded exclusively from verified Hugging Face official repositories.
   * Checksums (SHA-256) are validated during Docker container build time.
   * Model weights are baked into immutable container images; **dynamic runtime downloads from external URLs are strictly disabled**.
2. **Automated Dependency Auditing:**
   * CI/CD pipeline enforces `npm audit --audit-level=high` and `pip-audit`.
   * GitHub Dependabot alerts configured for automated security patches.
   * Container images scanned via **Trivy** in GitHub Actions; deployments block on any unpatched Critical or High CVEs.
3. **Execution Sandboxing:**
   * GPU worker containers run as non-root users (`uid 10001`).
   * Read-only root filesystems enabled (`read_only: true`), with strictly scoped `/tmp` mounts for temporary image array processing.

# 7. Logging, Incident Response & Disaster Recovery

### 7.1 Privacy-Compliant Structured Logging
Application logs must never become a backdoor for PII leakage:
* **Strict Scrubbing Rules:**
  * Raw image URLs, presigned URLs, and base64 payloads are **strictly redacted** from application logs (`[REDACTED_IMAGE_URL]`).
  * Email addresses are masked: `m***@example.com`.
  * User IP addresses are hashed using SHA-256 with a daily rotating salt prior to logging.
* **Log Transport:** Encrypted via TLS and ingested into AWS CloudWatch / Datadog with a 30-day retention window.

### 7.2 Incident Response Playbook: Compromised S3/R2 Bucket
If unauthorized access to room images or database records is detected:
1. **Immediate Revocation (Minute 0–15):** Rotate all Cloudflare R2 API tokens and AWS IAM access keys via Terraform/AWS CLI.
2. **Traffic Severing (Minute 15–30):** Temporarily route all `/api/v1/projects` endpoints to an HTTP 503 maintenance page via Cloudflare Edge Rules.
3. **Forensic Identification (Minute 30–60):** Inspect Cloudflare access logs to identify the exact scope of accessed object keys.
4. **Regulatory Notification:** If unblurred domestic photos were exfiltrated, notify affected users and European Data Protection Authorities within **72 hours** as mandated by GDPR Article 33.

# 9. Verification & Penetration Testing Protocols

Security controls must be verified via reproducible security test scripts in CI/CD and pre-launch penetration tests.

### 9.1 Automated Security Verification Suite (Jest / Supertest)

```typescript
/**
 * Project RoomCommerce - Automated Security Verification Tests
 * File: test/security/access-control.security-spec.ts
 */

import request from 'supertest';
import { INestApplication } from '@nestjs/common';

describe('Security & Privacy Control Verification', () => {
  let app: INestApplication;

  // TEST 1: BOLA / IDOR Protection
  it('[SEC-TEST-01] should reject access to project owned by another user', async () => {
    const attackerToken = 'Bearer user_attacker_jwt';
    const victimProjectId = '4b6a9c12-3211-4f81-a90b-04f8664b9e22';

    const response = await request(app.getHttpServer())
      .get(`/api/v1/projects/${victimProjectId}`)
      .set('Authorization', attackerToken);

    expect(response.status).toBe(403);
    expect(response.body.message).toContain('Access denied to requested project');
  });

  // TEST 2: Presigned Upload Content-Type & Size Boundary
  it('[SEC-TEST-02] should reject presigned upload requests for executable scripts', async () => {
    const userToken = 'Bearer user_valid_jwt';

    const response = await request(app.getHttpServer())
      .post('/api/v1/projects')
      .set('Authorization', userToken)
      .send({
        style_preset: 'JAPANDI',
        content_type: 'application/x-sh', // Malicious shell script
        file_size_bytes: 512,
      });

    expect(response.status).toBe(400);
    expect(response.body.message).toContain('Unsupported media type');
  });

  // TEST 3: Stripe Webhook Signature Spoofing
  it('[SEC-TEST-03] should reject Stripe webhooks with invalid cryptographic signature', async () => {
    const fakePayload = { type: 'checkout.session.completed', id: 'evt_fake_123' };

    const response = await request(app.getHttpServer())
      .post('/api/v1/billing/webhook')
      .set('stripe-signature', 't=1600000000,v1=invalid_hmac_signature')
      .send(fakePayload);

    expect(response.status).toBe(400);
    expect(response.body.message).toContain('Webhook signature verification failed');
  });

  // TEST 4: Immediate Data Purge Verification
  it('[SEC-TEST-04] should completely erase project and canvas records upon hard-purge request', async () => {
    const userToken = 'Bearer user_purge_test_jwt';

    // Trigger hard purge
    const purgeResponse = await request(app.getHttpServer())
      .delete('/api/v1/account/data')
      .set('Authorization', userToken)
      .send({ confirmation: 'DELETE' });

    expect(purgeResponse.status).toBe(200);

    // Verify projects are deleted from database
    const verifyResponse = await request(app.getHttpServer())
      .get('/api/v1/projects')
      .set('Authorization', userToken);

    expect(verifyResponse.body.projects.length).toBe(0);
  });
});
