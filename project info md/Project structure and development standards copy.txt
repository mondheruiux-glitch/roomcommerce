# 3. Reusable UI Component Organization (`packages/ui`)

To prevent component duplication and enforce the Atelier Design System (ADS), all reusable UI primitives, inputs, feedback, and display elements live in `packages/ui`. 

### 3.1 Component Directory Structure
Every component follows a clean, co-located directory structure:


```

packages/ui/src/primitives/button/
├── ads-button.tsx             # Primary component implementation
├── ads-button.types.ts        # Component props & variant interfaces
├── ads-button.test.tsx        # Unit tests (Vitest + React Testing Library)
├── ads-button.stories.tsx     # Isolated visual documentation (Storybook)
└── index.ts                   # Clean public export

```

### 3.2 Component Implementation Pattern
Every component is written as an accessible, forward-ref capable React component:

```tsx
// packages/ui/src/primitives/button/ads-button.tsx
import * as React from 'react';
import { cva, type VariantProps } from 'class-variance-authority';
import { cn } from '../../lib/utils';
import { AdsSpinner } from '../spinner/ads-spinner';
import type { AdsButtonProps } from './ads-button.types';

const buttonVariants = cva(
  'inline-flex items-center justify-center font-medium transition-colors focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-offset-2 disabled:pointer-events-none disabled:opacity-50 select-none active:scale-[0.98]',
  {
    variants: {
      variant: {
        primary: 'bg-brand-terracotta text-ink-inverted hover:bg-brand-terracotta-hover focus-visible:ring-ink-primary',
        secondary: 'bg-bg-surface text-ink-primary border border-border-default hover:bg-bg-subtle focus-visible:ring-ink-primary',
        danger: 'bg-bg-surface text-semantic-danger border border-semantic-danger hover:bg-semantic-danger-subtle focus-visible:ring-semantic-danger',
        ghost: 'text-ink-secondary hover:text-ink-primary hover:bg-bg-subtle focus-visible:ring-ink-primary',
      },
      size: {
        sm: 'h-8 px-3 text-xs rounded-sm gap-1.5',
        md: 'h-10 px-4 text-sm rounded-md gap-2',
        lg: 'h-12 px-6 text-base rounded-md gap-2.5',
      },
    },
    defaultVariants: {
      variant: 'primary',
      size: 'md',
    },
  }
);

export const AdsButton = React.forwardRef<HTMLButtonElement, AdsButtonProps>(
  ({ className, variant, size, isLoading, children, disabled, ...props }, ref) => {
    return (
      <button
        ref={ref}
        className={cn(buttonVariants({ variant, size, className }))}
        disabled={disabled || isLoading}
        aria-busy={isLoading}
        {...props}
      >
        {isLoading && <AdsSpinner aria-hidden="true" className="w-4 h-4 mr-2 animate-spin"/>}
        {children}
      </button>
    );
  }
);

AdsButton.displayName = 'AdsButton';

### Real-Time SSE Consumer Hook Example

```typescript
// apps/web/src/hooks/use-pipeline-stream.ts
import { useEffect, useState } from 'react';
import type { PipelineProgressEvent } from '@roomcommerce/contracts';

export function usePipelineStream(projectId: string | null) {
  const [progress, setProgress] = useState<PipelineProgressEvent null |>(null);
  const [isCompleted, setIsCompleted] = useState(false);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    if (!projectId) return;

    const eventSource = new EventSource(`/api/v1/projects/${projectId}/events`);

    eventSource.addEventListener('progress', (e) => {
      const data = JSON.parse(e.data) as PipelineProgressEvent;
      setProgress(data);
    });

    eventSource.addEventListener('complete', () => {
      setIsCompleted(true);
      eventSource.close();
    });

    eventSource.addEventListener('error', () => {
      setError('Connection interrupted. Retrying...');
    });

    return () => {
      eventSource.close();
    };
  }, [projectId]);

  return { progress, isCompleted, error };
}

```

# 6. API, Validation & Response Envelope Patterns

All backend endpoints use contract-first Zod schemas shared across frontend and backend via `@roomcommerce/contracts`.

### 6.1 Standardized API Envelopes

Every HTTP response conforms to an immutable JSON envelope:

```typescript
// Success Envelope
export interface ApiSuccessResponse<T> {
  success: true;
  data: T;
  meta?: {
    page?: number;
    total?: number;
    timestamp: string;
  };
}

// Error Envelope
export interface ApiErrorResponse {
  success: false;
  error: {
    code: string;
    message: string;
    details?: Array<{ field: string; message: string }>;
  };
}

```

### 6.2 NestJS Validation Pipe Integration

Incoming request bodies are validated using a custom `ZodValidationPipe` that converts validation failures into standard `ApiErrorResponse` structures:

```typescript
// packages/contracts/src/api/projects.schema.ts

# 7. Error-Handling Conventions

### 7.1 Unified Error Taxonomy

All system errors map to a standardized application error taxonomy:

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                                APPLICATION ERROR TAXONOMY                              │
├──────────────────────────┬──────────────┬──────────────────────────────────────────────┤
│ Error Code               │ HTTP Status  │ User-Facing Remediation Message              │
├──────────────────────────┼──────────────┼──────────────────────────────────────────────┤
│ `INVALID_IMAGE_FORMAT`   │ 400 Bad Req  │ Please upload a valid JPG, PNG, or HEIC file.│
│ `IMAGE_QUALITY_FAILED`   │ 422 Unproc   │ Image too blurry or dark. Retake with light. │
│ `ENTITLEMENT_EXCEEDED`   │ 403 Forbid   │ Free limit reached. Move-In Pass required.   │
│ `PROJECT_NOT_FOUND`      │ 404 Not Found│ This project has expired or does not exist.  │
│ `GPU_INFERENCE_TIMEOUT`  │ 504 Gateway  │ High server demand. Credits restored to you. │
│ `PURGE_CONFLICT`         │ 409 Conflict │ Deletion already in progress for this asset. │
└──────────────────────────┴──────────────┴──────────────────────────────────────────────┘

```

### 7.2 Global Exception Filter (NestJS)

All uncaught application exceptions pass through a single filter to ensure consistent responses and sanitize sensitive internal error stack traces from client exposure:

```typescript
// apps/api/src/common/filters/global-exception.filter.ts
import { ExceptionFilter, Catch, ArgumentsHost, HttpException, HttpStatus } from '@nestjs/common';
import { Response } from 'express';
import type { ApiErrorResponse } from '@roomcommerce/contracts';

@Catch()
export class GlobalExceptionFilter implements ExceptionFilter {
  catch(exception: unknown, host: ArgumentsHost) {
    const ctx = host.switchToHttp();
    const response = ctx.getResponse<Response>();

    let status = HttpStatus.INTERNAL_SERVER_ERROR;
    let code = 'INTERNAL_SERVER_ERROR';
    let message = 'An unexpected system error occurred. Please try again.';

    if (exception instanceof HttpException) {
      status = exception.getStatus();
      const res = exception.getResponse() as any;
      code = res.code || 'HTTP_ERROR';
      message = res.message || exception.message;
    }

    const payload: ApiErrorResponse = {
      success: false,
      error: { code, message },
    };

    response.status(status).json(payload);
  }
}

```

# 8. Environment & Secrets Management

To prevent runtime failures caused by missing environment variables, all configuration values are validated at boot time using `@t3-oss/env-core`:

```typescript

import { z } from 'zod';

export const env = createEnv({
  server: {
    NODE_ENV: z.enum(['development', 'test', 'staging', 'production']),
    PORT: z.coerce.number().default(4000),
    DATABASE_URL: z.string().url(),
    REDIS_URL: z.string().url(),
    CLOUDFLARE_R2_BUCKET: z.string().min(1),
    CLOUDFLARE_R2_ACCESS_KEY: z.string().min(1),
    CLOUDFLARE_R2_SECRET_KEY: z.string().min(1),

```

* **Secret Storage Hierarchy:** Production secrets are stored in **AWS Secrets Manager / Doppler** and injected into AWS ECS Fargate tasks as environment variables at launch. No raw `.env` files are checked into Git.

# 9. Branching Strategy & Code Review Standards

### 9.1 Trunk-Based Development

* The `main` branch is always deployable and protected against direct commits.
* Developers branch directly from `main` using short-lived feature branches:
* `feat/PROJ-101-image-dropzone`
* `fix/PROJ-204-qdrant-filter-bug`
* `chore/PROJ-305-update-deps`



### 9.2 Pull Request (PR) Requirements

To merge a PR into `main`, it must meet the following criteria:

1. **Automated CI Checks:** 100% pass on linting, TypeScript compilation, unit tests, and integration tests.
2. **Review Requirement:** Minimum of **one peer approval** from a senior engineer.
3. **Traceability:** PR title and description must reference an approved requirement ID (`FR-*`, `NFR-*`, `SEC-*`).
4. **Clean Git History:** Merges require **Squash and Merge** with Conventional Commit messaging (`feat: implement canvas hotspot pins (FR-401)`).
