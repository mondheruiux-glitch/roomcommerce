# 1. System Governance & Architecture

### 1.1 Component Naming Conventions
Atelier Design System uses a strict namespaced token and component taxonomy compatible with TypeScript, React, and Tailwind CSS:

* **Prefix:** `Ads` (PascalCase for React components: `<AdsButton />`, `<AdsHotspotPin />`).
* **CSS / Data Attributes:** `data-ads-*` and `.ads-*` (BEM-derived CSS variable mappings: `var(--ads-color-bg-canvas)`).
* **Token Structure:** `--ads-[category]-[property]-[variant]-[state]`
  * *Example:* `--ads-color-brand-terracotta-hover`, `--ads-space-inset-md`.

### 1.2 Documentation Format Standard
Every component in ADS must strictly adhere to the standardized 8-point specification rubric:
1. **Purpose & Usage Rules:** Operational intent, explicit "Do" and "Don't" mandates.
2. **Anatomy:** Sub-elements, structural hierarchy, and slot architecture.
3. **Variants & Sizes:** Matrix of available states, visual weights, and scale tiers.
4. **Design Tokens:** Exact CSS variables and raw hex/pixel values.
5. **Interaction & Accessibility:** Keyboard triggers, ARIA roles, focus mechanics, screen-reader behavior.
6. **Responsive Behavior:** Viewport adaptations (Desktop $\ge 1024\text{px}$, Tablet $768-1023\text{px}$, Mobile $< 768\text{px}$).
7. **Content Guidelines:** Character counts, typography tokens, capitalization, and tone.
8. **Dependencies & Related Components:** Composition boundaries and sub-primitives.

### 1.3 Semantic Versioning (SemVer) & Deprecation Policy
The design system packages (`@roomcommerce/tokens`, `@roomcommerce/ui`) follow strict SemVer:
* **MAJOR (`X.0.0`):** Breaking architectural changes (token renames, deleted variants, modified DOM structures breaking ARIA). Requires migration codemod.
* **MINOR (`0.X.0`):** New components, additional variants, backwards-compatible token aliases.
* **PATCH (`0.0.X`):** Bug fixes, accessibility aria-label enhancements, micro-contrast corrections.
* **Deprecation Horizon:** Deprecated components remain active for exactly one minor release cycle with an `@deprecated` JSDoc tag and a dev-mode console warning before removal.

### 1.4 Component Extension vs. Duplication Policy
To prevent component sprawl:
* **The Rule of Three:** Do not create a new component variant until the exact pattern appears across at least 3 distinct user journeys.
* **Composition via Slots:** Components must expose compound sub-components (`AdsModal.Header`, `AdsModal.Content`, `AdsModal.Footer`) rather than accepting dozens of boolean configuration props.
* **No Premature Generalization:** Build only what the approved PRD (`PRD-PRC-V1.0`) requires. Never build hypothetical elements (e.g., color-pickers, tree-views, or multi-tab carousels) ahead of approved roadmaps.

# 3. Primitives

### 3.1 `AdsButton`

#### 1. Purpose & Usage Rules

Triggers immediate actions.

* **Do:** Use `primary` exclusively for the single primary forward action per view (`"Redesign Room"`, `"Pay $14.99"`).
* **Don't:** Place two `primary` buttons adjacent to one another. Never use `primary` for destructive purge actions.

#### 2. Anatomy

`[Slot: IconLeft] + [Label: Text] + [Slot: IconRight] + [Aria-Live Spinner]`

#### 3. Variants & Sizes

* **Variants:** `primary` (Terracotta fill), `secondary` (Surface fill, Sandstone border), `tertiary` (Ghost, no border), `danger` (Red text/border for account purge).
* **Sizes:**
* `lg` ($48\text{px}$ height, $16\text{px}$ font, $24\text{px}$ padding horizontal) — Primary workflows, mobile conversion targets.
* `md` ($40\text{px}$ height, $15\text{px}$ font, $16\text{px}$ padding horizontal) — Standard dialog and toolbar buttons.
* `sm` ($32\text{px}$ height, $13\text{px}$ font, $12\text{px}$ padding horizontal) — Canvas floating utilities.



#### 4. Design Tokens

* Background Primary: `var(--ads-color-brand-terracotta)`, Hover: `var(--ads-color-brand-terracotta-hover)`.
* Text Primary: `var(--ads-color-ink-inverted)`. Radius: `var(--ads-radius-md)`. Focus Ring: `2px solid var(--ads-color-ink-primary)`.

#### 5. Interaction & Accessibility States

* **States:** Default, Hover, Active, Focus-Visible (`:focus-visible` offset $2\text{px}$), Disabled (`cursor: not-allowed`, opacity 0.5), Loading (`aria-busy="true"`, text visually hidden, spinner revealed).
* **A11y:** Native `<button type="button">`. If icon-only, requires mandatory `aria-label`.

#### 6. Responsive Behavior

* Stretches to `width: 100%` on mobile viewports ($< 768\text{px}$) within modal and form footers.

#### 7. Content Guidelines

* Strong verbs: 1–3 words in Title Case (`"Redesign Room"`, `"Unlock Pass"`). Never use `"Click Here"`.

#### 8. Dependencies

* `AdsSpinner`, `AdsIcon`.

### 3.2 `AdsBadge`

#### 1. Purpose & Usage Rules

Displays categorical status, stock state, or metadata tags.

* **Do:** Use to indicate verified stock availability (`"In Stock"`), match percentage (`"96% Match"`), or pass tiers (`"30-Day Pass"`).
* **Don't:** Embed links or interactive triggers directly inside a badge (use `AdsChip` for interactive selectors).

#### 2. Anatomy

`[Status Dot Indicator (Optional)] + [Badge Text: Tabular Mono / Label]`

#### 3. Variants & Sizes

* **Variants:** `neutral` (Stone), `success` (Olive/Green for in-stock), `warning` (Gold/Yellow for low-stock), `brand` (Terracotta tint for similarity confidence).
* **Sizes:** `sm` ($20\text{px}$ height, $11\text{px}$ font), `md` ($24\text{px}$ height, $12\text{px}$ font).

#### 4. Design Tokens

* Border: `1px solid var(--ads-border-color-default)`.
* Radius: `var(--ads-radius-full)`. Font: `var(--ads-font-family-mono)`.

#### 5. Interaction & Accessibility States

* Static element (`role="status"`). Inherits high contrast with a minimum of $4.5:1$ against surface backgrounds.

#### 6. Responsive Behavior

* Maintains fixed inline width across all screen widths.

#### 7. Content Guidelines

* Short nouns or numerical ratios (`"In Stock"`, `"Out of Stock"`, `"94% Match"`, `"$14.99"`).

#### 8. Dependencies

* None.

### 3.3 `AdsHotspotPin`

#### 1. Purpose & Usage Rules

Pinpoints the spatial coordinate of a matched real-world SKU on the 2D room canvas.

* **Do:** Position using normalized coordinates (`norm_x`, `norm_y`) to remain responsive on zoom.
* **Don't:** Clutter with labels on the canvas; display only the pin, expanding details on tap/hover.

#### 2. Anatomy

`[Concentric Focus Beacon (Animated Outer Ring)] + [Structural Core Dot] + [Accessible Touch Target Bounding Box]`

#### 3. Variants & Sizes

* **Variants:** `idle`, `hover`, `selected`.
* **Sizes:** Core diameter: $28\text{px}$; Touch Target: $48 \times 48\text{px}$ invisible bounding perimeter.

#### 4. Design Tokens

* Core Fill: `var(--ads-color-brand-terracotta)`.
* Outer Border: `2px solid #FFFFFF`. Shadow: `var(--ads-shadow-hotspot)`.
* Outer Pulse Ring: `var(--ads-color-brand-terracotta)`, Opacity: 0.6 to 0.0, Animation: `var(--ads-duration-pulse) infinite`.

#### 5. Interaction & Accessibility States

* **Focusable Button:** `<button aria-label="Coffee Table: Solid Oak Round Table, $249.99 at Target">`.
* **Keyboard:** Pressing `Tab` cycles through pins from top-left to bottom-right. Pressing `Enter` or `Space` selects pin and opens `AdsProductDrawer`.

#### 6. Responsive Behavior

* Visual size remains invariant ($28\text{px}$) across all viewports; coordinate recalculates via `transform: translate3d(calc(norm_x * 100%), calc(norm_y * 100%), 0)`.

#### 7. Content Guidelines

* Label exists in ARIA text only: `"{Category}: {Title}, {Price} at {Retailer}"`.

#### 8. Dependencies

* `AdsProductDrawer`, `AdsTooltip`.

#### 8. Dependencies

#### 1. Purpose & Usage Rules

Presents the 8 curated aesthetic design styles (Japandi, Mid-Century, Industrial, etc.) as selectable visual cards.

* **Do:** Limit selection to exactly 1 style preset in MVP.
* **Don't:** Use generic non-interior thumbnail images.

#### 2. Anatomy

#### 3. Variants & Sizes

#### 4. Design Tokens

#### 5. Interaction & Accessibility States

* Built as an accessible radio group: `<div role="radiogroup" aria-label="Interior Design Style Presets">`.
* Each item: `<div role="radio" aria-checked="true|false" tabindex="0">`. Keyboard arrow navigation enabled.

#### 6. Responsive Behavior

* Desktop: 4 columns $\times$ 2 rows. Mobile: 2 columns $\times$ 4 rows.

#### 7. Content Guidelines

* Title: 1 word (e.g., `"Japandi"`). Descriptor: Max 4 words (`"Warm wood, clean zen lines"`).

#### 8. Dependencies

* `AdsBadge`, `AdsIcon`.

### 4.3 `AdsDropzoneUpload`

#### 1. Purpose & Usage Rules

Ingests user-uploaded room photos (JPG, PNG, HEIC) up to 20MB.

* **Do:** Display clear privacy badges (EXIF-stripped, 7-day deletion) inside the intake container.
* **Don't:** Force drag-and-drop exclusively; must support native OS camera capture.

#### 2. Anatomy

`[Upload Icon] + [Primary Instruction Heading] + [Supported Formats Subtitle] + [Browse Button CTA] + [Privacy Trust Strip]`

#### 3. Variants & Sizes

* **Variants:** `idle`, `drag-over` (dashed line turns terracotta), `uploading` (progress ring), `error` (red border).
* **Sizes:** Minimum height $280\text{px}$ on desktop, $220\text{px}$ on mobile.

#### 4. Design Tokens

* Border: `2px dashed var(--ads-border-color-strong)`.
* Drag-Over Border: `2px dashed var(--ads-color-brand-terracotta)`. Background: `var(--ads-color-bg-subtle)`. Radius: `var(--ads-radius-lg)`.

#### 5. Interaction & Accessibility States

* Hidden file input `<input type="file" accept="image/jpeg,image/png,image/heic" />` triggered via keyboard `Enter`/`Space` on the container or button.
* Drag-and-drop events: `dragenter`, `dragleave`, `dragover`, `drop`.

#### 6. Responsive Behavior

* Mobile: Automatically switches primary label to `"Take Photo or Select File"`.

#### 7. Content Guidelines

* `"Supports JPG, PNG, HEIC up to 20MB. Photos auto-purged after 7 days for privacy."`

#### 8. Dependencies

* `AdsButton`, `AdsIcon`, `AdsProgressBar`.

`[Close Button] + [Retailer Logo & Name] + [Product Title] + [Verified Price Tag] + [Stock Badge] + [Dimensions Table (HxWxD)] + [Visual Similarity Score] + [Outbound Purchase Button] + [Mandatory FTC Affiliate Disclosure]`
