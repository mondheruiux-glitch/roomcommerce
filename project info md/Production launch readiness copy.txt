# 3. Database Migrations & Compatibility Strategy

### 3.1 Migration Execution Plan
* **Engine:** PostgreSQL 16 (AWS Aurora Serverless v2, multi-AZ enabled).
* **Migration Suite:** `0001_initial_schema.sql` through `0004_add_idempotency_keys.sql`.
* **Execution Pattern:** **Zero-Downtime Expand/Contract Architecture**.
  * All migrations introduce backward-compatible schema changes (e.g., nullable columns, default values).
  * No table renames, destructive drops, or column alterations occur during live deployments.
* **Pre-Migration Safety Gate:**
  * Automated snapshot taken via AWS RDS CLI immediately prior to migration step (`snap-pre-v1-launch-20261012`).
  * Migration executed via isolated ECS task container before traffic shift.

### 3.2 Schema Rollback Protocol
If migration scripts encounter an unhandled constraint violation:
1. Migration container halts deployment and exits with non-zero exit code (`1`).
2. Deployment pipeline halts automatically; traffic remains routed to previous stable task revision.
3. Automated rollback script (`down.sql`) executes within a database transaction block:
   ```sql
   -- Rollback script for release candidate v1.0.0-rc.3
   BEGIN;
   DROP TABLE IF EXISTS affiliate_click_events CASCADE;
   DROP TABLE IF EXISTS canvas_hotspots CASCADE;
   DROP TABLE IF EXISTS projects CASCADE;
   DROP TABLE IF EXISTS catalog_skus CASCADE;
   DROP TABLE IF EXISTS move_passes CASCADE;
   DROP TABLE IF EXISTS users CASCADE;
   COMMIT;

```

# 9. Security Review, Privacy Audit & Residual Risks

### 9.1 Privacy & Ephemeral Purge Verification

* **Automated 7-Day Purge:** Active lifecycle rule on Cloudflare R2 bucket confirmed (`Prefix: raw-uploads/`, `Prefix: renders/`, `Expiration: 7 Days`). Daily cron daemon verified to clean corresponding PostgreSQL metadata at 03:00 UTC.
* **1-Click Hard Purge (`PRV-02`):** Verified operating within $1.14\text{s}$ across database records and object storage assets.
* **Biometric Face Blur (`SEC-02`):** OpenCV YuNet model active in pre-diffusion pipeline with $31\times31$ Gaussian blur.

### 9.2 Residual Risks & Operational Caveats

1. **Illinois BIPA Legal Status:** Formal legal memorandum evaluating whether running OpenCV face-detection constitutes "biometric scanning" remains open with external counsel. Mitigation: No facial vector embeddings or biometric templates are generated, stored, or derived.
2. **Affiliate Link Staleness:** Retailers rotate product SKUs seasonally. Automated daily catalog crawlers (03:00 UTC) actively mark discontinued SKUs as `in_stock = false` to prevent broken links.

└────────────────────────────────────────────────────────────────────────────────────────┘

  └── Revision N-1 (Pre-warmed Standby Container for Instant Rollback)
          │
          ▼
 [AWS Aurora PostgreSQL 16]
  ├── Point-in-Time Recovery (PITR) enabled (1-second granularity, 35-day window)
  └── Cross-Region Automated Daily Snapshots (US-East-1 ➔ US-West-2)

```

### 10.1 Recovery Time & Point Objectives

* **RPO (Recovery Point Objective):** $< 5\text{ minutes}$ (Aurora continuous transaction log archiving).
* **RTO (Recovery Time Objective):** $< 15\text{ minutes}$ (ECS task revision rollback).

### 10.2 Automated Rollback Triggers

The ECS Deployment Circuit Breaker executes an immediate, automated rollback to `Revision N-1` if:

1. Container health checks (`GET /healthz`) fail for 3 consecutive intervals ($45\text{s}$).
2. API 5xx HTTP response rate exceeds $2.0\%$ during the initial 5 minutes of deployment.
3. Database connection pool reaches $100\%$ saturation immediately post-migration.

# 13. Staged Rollout Strategy & Deployment Schedule

To protect the platform against unanticipated GPU cold-start spikes or broken affiliate attribution, deployment will proceed via a **4-Stage Phased Canary Rollout**.

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                                STAGED ROLLOUT TIMELINE                                 │
└────────────────────────────────────────────────────────────────────────────────────────┘

  [Stage 1: Internal Dogfooding & Health Verification] ────► Duration: 4 Hours
  • 100% Internal Staff & QA (Whitelisted IPs / Test Accounts)
  • Validate live Stripe transactions ($14.99 charge) & real-world affiliate redirects
  • Assert 0 Sentry exceptions
            │
            ▼
  [Stage 2: 10% Canary Traffic (Pilot Market)] ────────────► Duration: 24 Hours
  • 10% of organic traffic routed via Cloudflare Edge Rules (US Geo-Targeted)
  • Monitor p90 inference latency (<15s) and GPU worker scaling
  • Verify conversion events (EV-101 to EV-302) in PostHog
            │
            ▼
  [Stage 3: 50% Staged Expansion] ─────────────────────────► Duration: 24 Hours
  • Expand routing to 50% of incoming users
  • Stress test catalog vector search under sustained multi-session load
  • Validate affiliate click tracking attribution yield
            │
            ▼
  [Stage 4: 100% General Availability (GA)] ───────────────► Full Production Live
  • Remove edge traffic constraints
  • Uncap marketing acquisition channels (Meta / TikTok Ads)
  • Transition to standard 24/7 SRE on-call rotation
