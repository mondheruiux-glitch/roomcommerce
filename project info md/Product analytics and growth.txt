# 1. North Star Metric & Executive KPI Hierarchy

Because Project RoomCommerce operates a dual monetization engine (episodic digital passes + downstream commerce affiliate commissions), the North Star Metric must measure **commercial discovery velocity** rather than raw social media virality or passive render counts.


```

┌────────────────────────────────────────────────────────────────────────────────────────┐
│                                  NORTH STAR METRIC (NSM)                               │
│                                                                                        │
│               Qualified Shoppable Outbound Sessions (QSOS) per Active Mover            │
│                                                                                        │
│  "The number of unique user sessions in which a user transforms a real room photo,     │
│   inspects at least one in-stock product hotspot, and clicks through to an authorized  │
│   retailer with an active affiliate tracking parameter."                               │
└────────────────────────────────────────────────────────────────────────────────────────┘

```

### Why QSOS Aligns User Value with Business Viability
1. **Validates Core User Value:** A user only executes an outbound click if the AI room design is aesthetically compelling, physically plausible, and populated with items that match their taste and budget.
2. **Drives Dual Revenue:** Outbound clicks directly monetize via affiliate commission cookies (4%–10% GMV) while signaling high user engagement, which drives conversion to the $14.99 30-Day Move-In Pass.
3. **Rejects False Engagement:** Filtering out passive renders prevents the team from optimizing for novelty users who view generations as free entertainment with zero purchase intent.

### Clarification on Episodic Retention vs. SaaS Retention
Standard SaaS apps measure 30/60/90-day recurring retention. Because home furnishing is **episodic** (occurring during a 30-day move-in window once every 1–3 years), measuring 12-month cohort retention as a core KPI creates misleading churn metrics. Instead, the team tracks:
* **30-Day Moving Window Velocity:** The number of distinct rooms (Living Room $\rightarrow$ Bedroom $\rightarrow$ Balcony) redesigned during the active pass period.
* **Long-Term Reactivation Rate:** Dormant users returning after 12+ months when signing a new lease or moving homes.

# 4. Privacy-Conscious Telemetry & Event Schema Specification

The telemetry framework is built around **strict privacy-by-design principles**. In compliance with GDPR Article 5 (Data Minimization) and CCPA, the event stream never ingests domestic room imagery, raw photo URLs, family names, precise GPS coordinates, or unmasked IP addresses.


```

┌────────────────────────────────────────────────────────────────────────────────────────┐
│                              TELEMETRY SANITIZATION GATEWAY                            │
└────────────────────────────────────────────────────────────────────────────────────────┘

[Client / Backend Event Trigger]
│
▼
[Sanitization Middleware]
├── Strip all image binaries, presigned URLs, and base64 strings.
├── Mask email addresses (`m***@example.com`).
├── Hash user IP addresses using SHA-256 with a daily rotating salt.
└── Normalize monetary figures to integers in USD cents (`price_cents`).
│
▼
[PostHog / Mixpanel Ingestion Endpoint]

```

### Detailed Experiment Specifications

#### `EXP-1`: Universal "Copy Shopping List & Open Retailers" Basket
* **Hypothesis:** Presenting a single action that copies all item specifications to the clipboard and opens external retailer tabs in sequence will increase downstream basket completion by $35\%$ compared to forcing users to click each individual hotspot pin sequentially.
* **Control:** User taps pin $\rightarrow$ opens drawer $\rightarrow$ clicks outbound link one item at a time.
* **Variant:** User clicks `"Open All 4 In-Stock Retailer Items"` $\rightarrow$ modal prompts clipboard copy and opens merchant tabs in order.
* **Sample Size Requirement:** $N = 1,200$ completed renders per variant ($\alpha = 0.05$, $1-\beta = 0.80$).

#### `EXP-2`: Real-Time Price-Tier Floor Indicators
* **Hypothesis:** Warning users when their selected budget ceiling is mathematically too low for their chosen aesthetic (e.g., setting $350 for an Industrial Living Room with an iron credenza) will reduce empty-result fallback generations by $50\%$ and improve user satisfaction.
* **Control:** Slider moves freely from $300 to $10,000 without dynamic hints.
* **Variant:** Slider displays dynamic minimum floor tags (e.g., *"Recommended min for Industrial: $550"*).
* **Sample Size Requirement:** $N = 800$ configurations per variant.

# 8. Customer Feedback Collection & Prioritization Framework

Qualitative signals contextualize quantitative metric anomalies. Feedback is gathered systematically via micro-interactions embedded directly within core workflows:


```

┌────────────────────────────────────────────────────────────────────────────────────────┐
│                              QUALITATIVE FEEDBACK CHANNELS                             │
└────────────────────────────────────────────────────────────────────────────────────────┘

[Channel A: Micro-CSAT on Canvas] (SCR-08)
├── Trigger: 5 seconds after render load.
└── Prompt: "How accurately does this redesign match your taste?" (1 to 5 Stars).
└── If 1–2 Stars: "What fell short?" [Checkbox: Sizing | Style Clashed | Too Expensive].
└── If 4–5 Stars: Prompt to save room or share with roommate.

[Channel B: Paywall Exit-Intent Prompt] (SCR-09)
├── Trigger: User closes the $14.99 Move-In Pass modal without purchasing.
└── Prompt: "What held you back from unlocking unlimited passes?"
└── Options: [Too expensive | Only need 1 room | Wanted to see more items | Moving later].

[Channel C: Dead-Link / Out-of-Stock User Flag] (SCR-08A)
├── Trigger: Persistent discrete icon in Product Drawer: "Report incorrect item or price".
└── Action: Submits SKU ID to Catalog Operations queue for instant re-crawling.

```

### Qualitative Prioritization Matrix
User feedback issues are scored weekly using an **Impact-Frequency Rubric**:
1. **Critical Cluster (Frequency $\ge 5\%$ of respondents):** Escalated directly to sprint backlog (e.g., *"The rug color in the image doesn't look like the Target photo"*).
2. **Niche Request (Frequency $< 1\%$):** Logged in product discovery research backlog without engineering action.
