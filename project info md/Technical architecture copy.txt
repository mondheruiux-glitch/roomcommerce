### 1.1 Division of Responsibilities

#### Frontend (Next.js 15 App Router / React 19)
* **Render UI & Interactive Canvas:** Displays the responsive studio, handles 2-finger zoom/pan on mobile, renders interactive SVG/Canvas hotspot pins using normalized coordinates (`norm_x`, `norm_y`).
* **Client-Side Edge Sanitization:** Strips EXIF/GPS telemetry before file transmission; computes quick client-side Laplacian image variance to immediately reject pitch-black or empty images without consuming server compute.
* **Direct-to-Storage Uploads:** Uploads raw image files directly to Cloudflare R2 using short-lived presigned PUT URLs, preventing heavy multi-megabyte payloads from traversing the application API servers.
* **Accessibility Parity:** Exposes the alternative WCAG 2.1 AA DOM specification table (`SCR-08B`) with synchronized state.

#### Core Backend API (NestJS / Node.js 22 LTS on AWS ECS Fargate)
* **Single Business Logic Monolith:** Organizes domain capabilities into isolated, clean modules (`Auth`, `Billing`, `Projects`, `Catalog`, `Commerce`, `InferenceOrchestrator`).
* **Job Queuing & Orchestration:** Pushes validated inference jobs into Redis-backed BullMQ queues; manages priority lanes (Paid Pass vs. Free Tier).
* **SSE Event Dispatcher:** Exposes a persistent Server-Sent Events (SSE) connection to stream real-time pipeline status to the frontend (`SCR-07`).
* **Affiliate Link Redirection & Attribution:** Resolves product click tokens, logs telemetry events (`EV-202`), appends affiliate network click IDs, and issues HTTP 302 redirects to merchants.
* **Stripe Webhook Ingestion:** Verifies cryptographic signatures, provisions 30-day Move-In Pass entitlements, and enforces the 60-generation fair-use ceiling.

#### Serverless GPU Worker Fleet (Python 3.11 / PyTorch on Modal / RunPod)
* **Isolated Compute Execution:** Runs containerized PyTorch workers with pinned CUDA drivers, completely separated from Node.js business logic.
* **Scale-to-Zero Cost Protection:** Workers scale to zero instances during idle traffic, eliminating baseline idle GPU costs ($600–$1,200/month per dedicated server).
* **Pipeline Execution:** Chains Depth Anything V2, SDXL ControlNet, SAM, and SigLIP, returning final WebP image assets and item bounding boxes to Cloudflare R2.

#### Database Layer (AWS Aurora PostgreSQL 16)
* **Relational Integrity:** Stores transactional entities, user profiles, Move-In Pass records, project associations, and normalized catalog metadata for 50,000 SKUs.
* **TTL & Deletion Tracking:** Manages scheduled purge timestamps (`purge_scheduled_at`) to guarantee hard data erasure within 7 days.

#### Vector Database (Managed Qdrant Cloud)
* **Multimodal Search Engine:** Indexes 768-dimensional SigLIP image embeddings with HNSW indexing, enforcing real-time payload filtering (`in_stock == true`, `category == target`, `price <= budget`).

#### Object Storage (Cloudflare R2)
* **Zero-Egress Asset Storage:** Stores raw input photos and generated 4K/1080p renders. Native bucket lifecycle rules enforce automated deletion after 7 days, eliminating storage bloat and ensuring regulatory compliance.

# 4. Authentication, Authorization & Session Management

### 4.1 Authentication Workflow
* **Passwordless Email Magic Links:** Eliminates password credential storage liabilities. When a user enters their email (`SCR-02`), the backend generates a cryptographically secure, single-use token (HMAC-SHA256, 15-minute expiration) and dispatches it via transactional email (Postmark / SendGrid).
* **OAuth 2.0 Providers:** Optional Google and Apple Sign-In flows using OpenID Connect (OIDC).
* **Guest Sessions:** Anonymous visitors receive an ephemeral `guest_session_id` stored in a secure, `SameSite=Lax`, `HttpOnly` cookie. This allows them to execute 1 free room redesign before creating an account.

### 4.2 Authorization & Role-Based Access Control (RBAC)


```

┌────────────────────────────────────────────────────────────────────────────────────────┐
│                              PERMISSION ENFORCEMENT RULES                              │
├─────────────────┬──────────┬──────────┬─────────────────┬──────────────────────────────┤
│ User Role       │ Free Run │ Paid Run │ Anchor Locking  │ Export 4K Clean Canvas       │
├─────────────────┼──────────┼──────────┼─────────────────┼──────────────────────────────┤
│ Anonymous Guest │ Max 1    │ No       │ No              │ No (Watermarked 1080p)       │
│ Registered User │ Max 2    │ No       │ No              │ No (Watermarked 1080p)       │
│ Move-In Pass    │ Unlimited│ Up to 60 │ Yes             │ Yes (Clean 4K WebP)          │
│ System Admin    │ N/A      │ Bypass   │ Yes             │ Yes (Diagnostics enabled)    │
└─────────────────┴──────────┴──────────┴─────────────────┴──────────────────────────────┘

```

Authorization is enforced via NestJS Guards (`@UseGuards(JwtAuthGuard, EntitlementGuard)`). The `EntitlementGuard` validates the database state:
```typescript
// Entitlement Verification Rule
const hasActivePass = user.movePasses.some(
  pass => pass.expiresAt > new Date() && pass.generationsExecuted < 60
);
if (!hasActivePass && user.freeRendersUsed >= 2) {
  throw new ForbiddenException({
    code: 'PASS_REQUIRED',
    message: 'Free generation limit reached. Please purchase a Move-In Pass.'
  });
}

```

# 7. Background Processing, Queues & Error Handling

Heavy ML tasks cannot block HTTP request threads. Background processing uses **BullMQ with Redis**.

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                                BULLMQ JOB LIFECYCLE FLOW                               │
└────────────────────────────────────────────────────────────────────────────────────────┘

  [Client Request] ──► Pushed to Queue: `room-inference-queue`
                             │
            ┌────────────────┴────────────────┐
            ▼                                 ▼
   Lane A: High-Priority             Lane B: Standard
   (Paid Move-In Pass Holders)       (Free Tier Users)
            │                                 │
            └────────────────┬────────────────┘
                             │
                             ▼
  [Worker Processes Job] ──► Timeout Budget: 25.0s (Hard Deadline)
                             │
            ┌────────────────┴────────────────┐
            ▼                                 ▼
        (Success)                          (Failure)
            │                                 │
   Save R2 Renders & Hotspots                 ├── Attempt 1 & 2: Exponential Backoff (2s, 5s)
   Emit SSE: `complete`                       └── Final Fail: Move to `Dead-Letter Queue`
                                                  Emit SSE: `error` (Credits Restored)

```

### Circuit Breaker & Timeout Strategy

* **Hard Job Timeout:** If the GPU serverless runner does not respond within $25.0\text{ seconds}$, the BullMQ worker marks the job as timed out, restores the user's generation credit, and notifies the client via SSE.
* **Dead-Letter Queue (DLQ):** Failed jobs are sent to `room-inference-dlq`. Alerts trigger in Slack/PagerDuty if the DLQ exceeds 5 items in a 10-minute window.
* **Idempotency Guarantee:** Every render job takes an idempotency key (`idempotency_key = hash(project_id + user_id)`). Re-submitting the same request returns the existing job ID rather than spawning duplicate GPU tasks.

# 11. Scalability, Performance SLAs, Backup & Recovery

### 11.1 Service Level Agreements (SLAs)

* **API Availability:** $99.9\%$ monthly uptime.
* **Warm Pipeline Generation Latency:** $\le 13.0\text{ seconds}$ average; $\le 15.0\text{ seconds}$ (p90).
* **Hotspot Tap Response Time:** $\le 150\text{ milliseconds}$ to render product drawer.
* **Vector Search Latency:** $\le 50\text{ milliseconds}$ per query in Qdrant.

### 11.2 Disaster Recovery (DR) & Backup Policy

* **Recovery Point Objective (RPO):** $< 1\text{ hour}$ (Aurora continuous automated backups with point-in-time recovery).
* **Recovery Time Objective (RTO):** $< 30\text{ minutes}$ (ECS Fargate infrastructure defined via Terraform / CloudFormation).
* **Ephemeral Data Exemption:** Raw user images and temporary room renders are not backed up across regions, complying with the 7-day privacy purge policy.

# 12. Security, Privacy & Regulatory Considerations

### 12.1 GDPR & CCPA Compliance Architecture

1. **Zero Model Training Guarantee:** User room imagery is strictly quarantined and excluded from foundation model training datasets (`PRV-01`).
2. **Automated 7-Day Storage Purge:** Cloudflare R2 enforces bucket lifecycle rules that hard-delete files after 7 days (`SEC-01`). A companion database cron worker removes associated records.
3. **Automated Biometric Obfuscation:** The serverless ingestion pipeline runs OpenCV YuNet face detection on every upload, applying a $31\times31$ Gaussian blur to domestic faces and family portraits before inpainting (`SEC-02`).
4. **Immediate Right-to-Erasure:** A user can trigger an instant hard purge via `/account` (`PRV-02`), deleting all projects, images, and pins within 60 seconds.

### 12.2 Commercial Regulatory Compliance (FTC / ASA)

* Every screen presenting shoppable product pins (`SCR-08`, `SCR-08A`, `SCR-08B`) visibly includes mandatory legal disclaimers: *"We earn affiliate commissions from qualifying purchases made via links on this page."*
